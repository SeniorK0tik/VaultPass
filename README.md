# Сейф

Локальное хранилище паролей, заметок, ключей API и документов.
Реализация макета `Сейф - UI.dc.html` на Rust: ядро — обычный крейт,
интерфейс — HTML и CSS из макета, оболочка — Tauri 2. Собирается под
Windows и Debian из одного дерева исходников.

Экраны макета и файлы соотносятся так:

|---|---|---|
| 1a | Палитра поиска, Enter копирует | `ui/js/quick.js`, режим «Палитра» |
| 1b | Палитра с полями записи справа | `ui/js/quick.js`, режим «Палитра с полями» |
| 1c | Мини-окно у трея | `ui/js/tray.js` |

| 1e | Плотная таблица | `ui/js/main.js`, `renderTable` |
| 1f | Разблокировка | `ui/js/unlock.js` |
| 1g | Карточка записи | `ui/js/editor.js` |
| 1h | Генератор | `ui/js/generator.js` |
| 1i | Настройки | `ui/js/settings.js` |

Вид главного окна (1d или 1e) и вид быстрого окна (1a, 1b или 1c)
переключаются в настройках — оба варианта макета остаются рабочими.

Снимки всех девяти экранов лежат в `docs/screens/`. Пересобрать их можно без
полной сборки приложения — экраны открываются в обычном браузере с подставным
мостом `__TAURI__`:

```bash
./tools/preview/run.sh          # пересобрать снимки
./tools/preview/run.sh --serve  # открыть экраны в браузере вручную
```

## Как устроено шифрование

Между мастер-паролем и данными стоит промежуточный ключ:

```
мастер-пароль ──Argon2id(соль, 64 МиБ / 3 прохода / 4 потока)──► KEK_m ─┐
                                                                        ├─► обёртка DK
ключ восстановления ──HKDF-SHA256(соль)───────────────────────► KEK_r ─┘

DK (32 байта системной энтропии) ──XChaCha20-Poly1305──► всё содержимое сейфа
```

Что это даёт:

- **Смена мастер-пароля мгновенна.** Переписывается только обёртка ключа
  данных, записи не перешифровываются — значит, операция не может испортить
  сейф на полпути.
- **Два способа входа ведут к одному ключу.** Ключ восстановления — не
  запасной пароль, а вторая обёртка того же `DK`.
- **Подмена параметров не помогает.** Стоимость Argon2id входит в
  дополнительные данные AEAD: понизить её в файле, чтобы удешевить перебор,
  нельзя — не сойдётся тег.
- **По файлу не видно ничего.** Названия, логины, адреса и теги лежат внутри
  шифротекста; снаружи только соли, нонсы и параметры. Даже число записей
  снаружи неизвестно.

Файл пишется атомарно: рядом готовится новый, сбрасывается на диск и лишь
затем занимает место старого. Перед каждой записью прежняя версия уходит в
`backups/`, где хранятся пять последних.

Настройки лежат отдельно, в открытом `config.json`. В них нет секретов, зато
горячая клавиша нужна ещё до разблокировки — иначе ею нельзя было бы вызвать
окно, чтобы сейф разблокировать.

### Где именно живут секреты

Граница IPC проведена так, чтобы пароль не попадал в вебвью без нужды:

- списки и карточки получают запись **без пароля** — только признак его наличия
  и оценку стойкости;
- «Копировать» кладёт значение в буфер **из Rust**, интерфейс его не видит;
- «Показать» поднимает наверх одно поле одной записи по отдельному запросу;
- прежние пароли из истории не выводятся никогда — только длина и дата;
- форма редактирования получает пароль целиком: там его нужно править.

Ключ данных живёт только внутри структуры `Vault`, а она — только в состоянии
процесса. «Заблокировать» — это не флаг, а уничтожение структуры: `Drop`
затирает ключ и расшифрованные строки (`zeroize`).

## Сборка и запуск

Всё делается одной командой `./x` — помнить заклинания cargo не нужно.

```bash
./x setup          # поставить всё необходимое (один раз)
./x test           # 68 тестов
./x dev            # запустить приложение
```

Полный список:

| Команда | Что делает |
|---|---|
| `./x setup` | системные библиотеки, нужный Rust, `tauri-cli` |
| `./x test` | тесты ядра |
| `./x check` | проверка типов всего проекта |
| `./x lint` | формат и clippy — ровно как в CI |
| `./x dev` | запуск с пересборкой на лету |
| `./x run` | собрать релизный двоичный файл и запустить |
| `./x build` | установщики для текущей ОС |
| `./x version 1.5.0` | поднять номер версии во всех трёх местах сразу |
| `./x release 1.5.0` | версия → проверки → тесты → сборка |
| `./x screens` | пересобрать снимки экранов |
| `./x preview` | открыть экраны в браузере без сборки Tauri |

`./x build` кладёт в `target/release/bundle/`:

| Пакет | Размер | Когда нужен |
|---|---|---|
| `deb/Seif_1.4.0_amd64.deb` | ~3 МБ | Debian и Ubuntu: ставится через `apt`, тянет системные GTK и WebKit |
| `appimage/Seif_1.4.0_amd64.AppImage` | ~104 МБ | любой дистрибутив: внутри лежат все зависимости, отсюда и размер |

### Windows

Три пути, по убыванию надёжности:

| Путь | Что получается | Чего стоит |
|---|---|---|
| **CI по тегу** (рекомендуется) | `.msi` и `.exe` | ничего — `.github/workflows/build.yml` уже настроен |
| **Сборка на Windows** | `.msi` и `.exe` | нужна машина с Visual Studio Build Tools («Разработка классических приложений на C++») и WebView2 — в Windows 11 он уже есть |
| **Кросс-сборка с Linux** | **только `.exe`** (NSIS) | `./x build windows` доставит `cargo-xwin` и цель `x86_64-pc-windows-msvc` |

`.msi` собирается **только под Windows**: его делает WiX, который под Linux не
работает. NSIS-установщик кросс-собрать можно, но сам Tauri называет это
«крайним средством» и тестирует заметно меньше обычной сборки — годится
проверить `.exe`, не поднимая виртуальную машину, но не выпускать версию.

Выпуск версии для обеих платформ:

```bash
./x release 1.5.0
git commit -am "Версия 1.5.0" && git tag v1.5.0 && git push --tags
```

На самой Windows всё то же самое делает `x.ps1` — те же команды, тот же вид:

```powershell
.\x.ps1 setup     # проверит Rust, Build Tools, WebView2, доставит tauri-cli
.\x.ps1 test
.\x.ps1 build     # .msi и .exe в target\x86_64-pc-windows-msvc\release\bundle\
```

Что нужно поставить на машине с Windows заранее:

1. **Rust** — [rustup.rs](https://rustup.rs). Версию 1.90 из `rust-toolchain.toml`
   он доставит сам.
2. **Visual Studio Build Tools** с рабочей нагрузкой «Разработка классических
   приложений на C++» —
   [visualstudio.microsoft.com/visual-cpp-build-tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/).
   Без неё нет компоновщика `link.exe`, и сборка падает с невнятной ошибкой;
   `.\x.ps1 setup` проверяет это заранее и говорит прямо.
3. **WebView2** — в Windows 11 уже есть. В Windows 10 нужен для запуска
   (`.\x.ps1 dev`); готовому установщику не нужен — он доставит его сам.

Node, Python и прочего не требуется: интерфейс — статические файлы без сборщика.

Установщики не подписаны, поэтому при первом запуске SmartScreen покажет
предупреждение. Подпись — отдельный сертификат и отдельный шаг.

### Версия компилятора закреплена

`rust-toolchain.toml` фиксирует Rust 1.90. Это не прихоть: на 1.96 сборка
падает с SIGSEGV внутри `glib-macros 0.18.5` — крейта из стека gtk-rs, на
котором Tauri рисует окна в Linux. Версию этого крейта задаёт сам Tauri,
поднять её из проекта нельзя. Проверено, что дело не в размере стека
(падает и с `RUST_MIN_STACK=512 МиБ`) и не в повреждённых исходниках.
Закрепление снимается, когда Tauri перейдёт на gtk-rs 0.19+.

## Особенности платформ

| | Windows | Debian, X11 | Debian, Wayland |
|---|---|---|---|
| Глобальная горячая клавиша | да | да | через портал XDG, не во всех окружениях |
| Значок в трее | да | да | да |
| Мини-окно у трея встаёт к значку | да | у края экрана | **нет**, только перетаскиванием |
| Автозаполнение (эмуляция ввода) | да | да | **нет** |

Куда встанет мини-окно (1c), приложение решает не везде. Прямоугольник значка
сообщает только трей Windows — GTK об этом молчит, и на Debian окно уходит в
угол рабочей области, где панель стоит почти всегда. Под Wayland положение
окна назначает композитор, и попросить его о другом месте нельзя: GNOME
открывает мини-окно посреди экрана. Поэтому окно двигается мышью за полосу
заголовка: этот путь идёт через композитор и работает везде. А булавка в шапке
закрепляет окно — закреплённое не прячется при щелчке мимо и остаётся там, куда
его поставили. Место запоминается и подставляется при следующем открытии — на
Windows и X11, где положение окна вообще можно задать.

Автозаполнение под Wayland невозможно не по недоработке: протокол запрещает
отправку нажатий в чужое окно — тем же запретом он защищает от клавиатурных
шпионов. Приложение сообщает об этом прямо, а не молчит. Пароль в этом случае
копируется в буфер.

## Чего в этой версии нет

Сознательные пропуски — макет их показывает, но реализация отложена:

- **Вычисление кодов TOTP.** Строка `otpauth://` хранится, переносится и
  шифруется вместе с записью, но шестизначные коды не считаются. Поля 2FA на
  экранах говорят об этом прямо, а не показывают выдуманные цифры.
- **Вход по биометрии** (Windows Hello, отпечаток). Переключатель на экране
  настроек есть, поддержки пока нет.
- **Сверка с базами утечек.** Аудит работает целиком на устройстве: считает
  энтропию, ищет повторы и давние пароли. Проверка по HIBP требует сетевого
  запроса — это отдельное решение и отдельное согласие пользователя.
- **Облачная синхронизация.** Файл сейфа обычный, его можно положить в
  синхронизируемую папку: содержимое всё равно зашифровано.
- **Импорт из KeePass, Bitwarden, 1Password.** Формат хранилища свой.

Оценка стойкости чужого пароля приближённая — по составу символов, а не по
словарям: «Пароль123» получит здесь незаслуженно высокий балл. Подключение
zxcvbn заменит ровно одну функцию, `generator::estimate_strength`.

## Как проверить, что всё работает

```bash
./x test        # 68 тестов: 48 в ядре, 20 в платформенном слое
./x lint        # формат и clippy с -D warnings, ровно как в CI
./x dev         # приложение с пересборкой на лету
```

При первом запуске сейфа ещё нет — экран предложит придумать мастер-пароль
(не короче 8 символов) и создаст хранилище в `~/.local/share/seif/seif.vault`
(на Windows — `%APPDATA%\Seif\`).

Что стоит попробовать руками:

| Проверка | Как |
|---|---|
| Создание и разблокировка | Придумать мастер-пароль, закрыть приложение, открыть снова |
| Секреты не в вебвью | `strings ~/.local/share/seif/seif.vault \| grep -i <название записи>` — ничего не найдёт |
| Копирование с очисткой | Скопировать пароль, подождать 30 с, вставить — буфер пуст |
| Автоблокировка | Настройки → 1 мин, не трогать окно минуту |
| Горячая клавиша | `Ctrl+Shift+Space` поверх любого окна |
| Оба вида главного окна | Настройки → Общие → Вид главного окна |
| Все три вида быстрого окна | Настройки → Быстрый доступ → Вид быстрого окна |
| Резервные копии | Изменить пару записей, затем Настройки → Резервные копии |
| Ключ восстановления | Настройки → Безопасность → Ключ восстановления, затем перезапуск и вход по нему |

Экраны можно посмотреть и без сборки приложения — `./x preview` откроет их
в браузере с подставными данными.

## Журнал

Приложение ведёт журнал: запуск с описанием окружения, действия с сейфом,
все отказы IPC и необработанные ошибки интерфейса.

```
Linux    ~/.local/share/app.seif.vault/logs/seif.log
Windows  %LOCALAPPDATA%\app.seif.vault\logs\seif.log
```

Достать можно тремя способами:

| Способ | Когда удобен |
|---|---|
| **Настройки → Диагностика** | из самого приложения: путь, последние строки, кнопка «Скопировать журнал» |
| `./x logs` | из терминала; `./x logs -f` — следить за появлением строк |
| Настройки → Диагностика → «Открыть папку» | если нужен сам файл |

**Секретов в журнале нет.** Туда попадают имена команд, коды ошибок и их
тексты — но не пароли, не логины и не названия записей. Аргументы команд не
записываются намеренно: в них бывают секреты. Единственное исключение —
UUID записи в ошибке «запись … не найдена», но по нему без самого сейфа
ничего не узнать.

Необработанные ошибки разметки перехватываются через `window.onerror` и
`unhandledrejection` и уходят в тот же файл: иначе они оставались бы в консоли
вебвью, куда никто не заглядывает, и на экране просто ничего не происходило бы.
